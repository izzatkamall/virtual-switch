Virtual Switch: Project Report

Operating Systems, Fall 2026 · Muhammad Izzat Kamal (BSAI24078)

1. Overview

The switch is one process (./switch port n [config]). Hosts connect over TCP and each gets one of n ports. Frames use the fixed 17 byte header. The switch learns source MACs, forwards to the learned port, and floods broadcasts and unknown destinations inside the VLAN. A separate process, swctl, talks to the switch over a UNIX socket and reads live counters from shared memory. Every thread sleeps on a condition variable, semaphore, sigwait or a blocking socket call, so nothing busy waits. Periodic work (aging, token refill) uses pthread_cond_timedwait on a stop condition so shutdown wakes it straight away.

2. Threads

Figure 1. Threads of the switch. Each connected port has its own rx and tx thread; the six threads on the right exist once. The dashed arrow is port 0’s rx putting a frame on port 1’s queue.
ThreadCountWhat it does
main1Blocks the signals, starts the others, then loops: wait on the free_ports semaphore (with a timeout), accept, attach the host to a free port. On timeout it sends a switch full frame and closes. At the end it runs the shutdown and joins everything.
rx (per port)≤ nReads frames with read_full, learns the source MAC, looks up the destination and puts one refcounted copy of the frame on each output queue. Never blocks on another host. On EOF it cleans up the port and posts the semaphore.
tx (per port)≤ nWaits on the port's not_empty condition, picks the next frame by weighted round robin (5:3:1 with aging), waits for a token if the port is rate limited, and writes it.
signal1sigwait on INT/TERM (shutdown), HUP (reload config), USR1 (dump MAC table).
admin1Accepts swctl on /tmp/vswitch.sock, runs one command, sends the reply.
rate / aging1 + 1Refill every port's token bucket every 100 ms / remove MACs older than mac_age every second.
logger1Takes lines off the log queue and writes them to switch.log with timestamps. Other threads never wait on the disk.

3. Locks and what they protect

LockProtects
attach_lockChoosing a port for a new host, and swctl shutdown/up. Keeps the free_ports semaphore count in step with the ports' enabled flags.
port lock (one per port)Everything in struct port: fd, state (FREE/UP/CLOSING/DONE), enabled, draining, the three QoS rings and WRR state, vlan, trunk, mirror_to, rate, tokens. Used with the conditions not_empty (tx waits for frames) and done (shutdown waits for the port to close).
MAC bucket locks (16)The linked list of entries in that bucket (mac, port, last_seen). Different MACs usually hash to different buckets so learning on many ports runs in parallel.
count_lockTable wide numbers: total count, max_entries, max_per_port and the per port MAC counts used for port security.
shm mutexThe per port in/out/dropped/mirrored counters in /dev/shm/vswitch_stats. It is PTHREAD_PROCESS_SHARED so swctl stats can lock it from another process.
cfg_lockThe current struct config. Readers copy it out with get_config(); SIGHUP swaps in a new one.
log lockThe 1024 line log queue, its head/count and the dropped counter (condition not_empty wakes the logger).
stop_lockThe stopping flag. stop_cond is used for every timed wait so shutdown can wake them.

Not locks but also shared: the free_ports semaphore (counts free ports) and an atomic_int reference count in each frame. A broadcast is stored once; every queue that takes it adds a reference and the last pkt_put frees it.

4. Lock order

Locks are always taken in this order, and a thread never holds two port locks at the same time:

  1. attach_lock
  2. one port lock
  3. MAC bucket locks, in ascending bucket index when more than one is needed
  4. count_lock
  5. leaf locks: shm mutex, cfg_lock, log lock, stop_lock. Nothing is locked while holding one of these.

How the code keeps to it:

  • Forwarding touches several ports but one at a time. forward() reads the input port's VLAN and mirror setting under its lock and unlocks, then port_enqueue() locks each output port separately. Mirror copies are queued after unlocking the port, so a frame from port 0 mirrored to port 2 never holds both locks.
  • MAC insert takes the bucket lock, then count_lock. If the table is over its limit, eviction runs after the bucket is unlocked, scans the buckets one at a time, then relocks the chosen bucket and only removes the entry if its last_seen did not change in between.
  • clear mac locks buckets 0 to 15 in order, then count_lock, and unlocks in reverse.
  • swctl shutdown takes attach_lock then the port lock, then waits on the port's done condition (which releases the port lock) for at most 2 seconds while tx drains the queue. The rx thread's cleanup only needs the port lock and bucket locks, never attach_lock, so it can always finish.
  • Counters, config and logging are leaves, so they can be used from anywhere (for example the dropped counter is increased inside port_enqueue while the port lock is held).

5. A real bug: priority queues that turned into FIFO

What happened. For item 6 each port has three queues served 5:3:1, plus aging so low priority never starves. My first aging rule was per frame: if the oldest frame in any queue had waited more than 200 ms, send it next. tests/test_priority.py, where host B stops reading while A sends 40 low, then 40 normal, then 40 high frames, then counts how many frames B gets after the last high one, failed 3 times out of 5. The high frames were coming out last, which is what plain FIFO would do.

How I found it. The failure only showed up with a long backlog, which pointed at aging rather than WRR. While B is not reading, the queues fill up and stay full. Every frame waits more than 200 ms, so every frame counts as "aged", and "send the oldest aged frame" is just FIFO. Aging was overriding WRR all the time instead of only rescuing a starved queue.

The fix. Aging is now per queue, not per frame. A queue gets one extra turn only if it is non empty and has not been served for 200 ms (measured from the later of its last service and its head frame's arrival). After that turn its timer resets and normal 5:3:1 continues. I added test_old_backlog in tests/test_qos.c, which uses fake time: 40 frames per queue, all "old", and checks that 27 pops give exactly 15 high, 9 normal and 3 low. test_priority.py now passes every time, with the pattern HHHHHNNNL visible in the output.

A related surprise. Before that, priorities did nothing at all: the kernel's socket send buffer (a few MB) accepted every frame immediately, in order, so our queues were always empty. Setting SO_SNDBUF to 8 KB on each host socket makes the backlog build up in our queues where WRR can reorder it.

6. Items completed and testing

Tier 1: all of items 1 to 5. Tier 2: all of items 6 to 13 (QoS with WRR and aging, token bucket rate limit, VLANs and trunk, port mirroring, live reconfiguration, swctl with shared memory counters, signals, logger thread). Tier 3: not attempted.

Testing. make check runs 3 C unit tests and 12 live tests, each against a fresh switch, and stops it with SIGINT (it must exit 0). The live tests cover forwarding and learning, a frozen host that never reads (other hosts still get 100/100 frames), broadcast storms with hosts joining and leaving, MAC flooding (port security), the port limit and switch full, priorities, rate limiting, VLANs, admin commands, mirroring, SIGINT in five situations, and a stress test that runs traffic, host churn and about 30,000 random swctl commands at once and then checks that all 8 ports come back free. The build uses -Wall -Wextra -Werror.

ThreadSanitizer and valgrind. make tsan builds everything with -fsanitize=thread and runs the whole suite; make valgrind runs every live test with the switch under valgrind (--leak-check=full, leaks counted as errors). The first TSan run found one real race: at shutdown, close_all_ports() set a port's state back to FREE after joining its rx thread but without taking the port lock, while rx threads of other ports could still be reading that field in port_enqueue(). It only happened when SIGINT arrived during a broadcast storm. The fix was to do that write under the port lock. After that, three full TSan runs gave no reports, and under valgrind every switch run ended with 0 errors, all heap blocks freed and no file descriptors left open apart from stdin/stdout/stderr. host and swctl are also clean under both tools.
